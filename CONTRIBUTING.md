# Contributing to xoxo

Thanks for your interest in contributing to xoxo.

This project is open source and welcomes contributions from everyone. To keep the codebase consistent and maintainable, all contributions must follow the project’s Kiro-based workflow and coding standards.

## Before You Start

Please read:
- `README.md`
- `CONTRIBUTING.md`
- Any Kiro steering or project guidance files in the repository
- Existing issues and pull requests related to your idea

## Required Workflow

All contributors must use Kiro when working on this project.

Please use Kiro to:
- Understand the project structure and conventions.
- Follow the established coding standards and architecture.
- Review or update project steering files when needed.
- Keep changes aligned with the project’s existing patterns.

If your contribution does not follow the Kiro workflow, it may be rejected or requested for revision.

## What You Can Contribute

We welcome:
- Implementing cool new features
- Providing resources or documentation that help users understand how to use xoxo
- Bug fixes
- Feature improvements
- Documentation updates
- Tests
- Refactoring that improves clarity or maintainability

## How to Contribute

1. Open an issue first for major changes.
2. Fork the repository.
3. Create a branch for your work.
4. Use Kiro to plan and implement your changes according to project standards.
5. Make sure your code is clean, readable, and tested.
6. Submit a pull request with a clear description of what changed and why.

## Coding Standards

Please:
- Follow the existing style and architecture.
- Write clear, maintainable code.
- Add or update tests when appropriate.
- Keep changes focused and small.
- Avoid introducing unnecessary dependencies.

## Pull Request Expectations

A good pull request should:
- Explain the purpose of the change.
- Reference any related issue.
- Describe how you tested it.
- Include screenshots or examples if relevant.

We may ask you to revise your PR if it does not follow the project’s Kiro standards or review expectations.

## License

## Code of Conduct

Please be respectful, constructive, and collaborative in all discussions and reviews.

## Questions

If you have questions before contributing, open an issue or start a discussion.
